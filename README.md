# ConfluentContour

A Fortran Lambert solver built on the contour-integral formulation of Negrete and Abdelkhalik (2024), *Exact Solution to the Lambert Problem Using Contour Integrals* (AIAA JGCD, DOI: 10.2514/1.G008499). It covers elliptic, parabolic and hyperbolic transfers and both multi-revolution branches. This repository also contains ContourSimple, a short version of the same method, a dimensional Fortran API, and a MATLAB reference of the paper's method.

- **Root extraction.** The main path is the *confluent* contour step. This is the exact zero-radius limit of the paper's contour ratio, which equals a Householder step. It is order 4 on elliptic arcs and order 3 on hyperbolic, near-parabolic and very short hyperbolic arcs. Derivatives come in closed form from the ODE $\sin v\,F' + 3\cos v\,F = \sqrt2$, in real arithmetic. A converged step counts as verified. Otherwise sign-bracketed small trapezoidal contours run, with interval contours and a certified bisection contour as safeguards.
- **Tables.** About 66 KB of compiled-in tables refine the starting estimates in the Lancaster–Blanchard parameter, so most solves need one step. No data file is read at run time. Multi-revolution feasibility is usually decided from a tabulated $t_{\min}$; requests within about $3\times10^{-4}$ of it use the exact minimum. `tools/` regenerates the tables.
- **Batch.** `contour_batch` processes cases in stages for throughput and matches `contour_one` bit for bit.
- **ContourSimple** (`fortran/contour_simple.f90`, about 310 lines, in the style of the Izzo and Gooding routines) keeps the half-anomaly time function, ODE derivatives, order-3 confluent step and velocity recovery. It replaces the tables, sampled contours, special coordinates and safeguards with three closed-form cubic Hermite starters:
  - elliptic: $v^2$ in $(t_p/t)^{1/3}$;
  - short-way hyperbolic: $w^2$ in $(t/t_p)^2$;
  - long-way hyperbolic: the asymptote $T\sim\sqrt{-b}\,(y_0+b)\,e^{-w/2}$.

  It also uses Halley iteration for the multi-revolution minimum time, and Newton in $\sqrt y$ for very short short-way hyperbolas.

The full description of the method, its differences from the paper, and measurements are in [ConfluentContourSolver.md](ConfluentContourSolver.md). Timing comparisons against other Lambert solvers (ivLam, Izzo, Gooding, eLam, ...) live in [Lamberts-Comparison](https://github.com/Ossama-Abdelkhalik-Lab/Lamberts-Comparison), which uses this repository as a submodule.

## Files

| File | Role |
| --- | --- |
| `fortran/confluentcontour.f90` | The solver (module `confluentcontour`): `contour_initialize`, `contour_one`, `contour_batch`; low-level `prepare_geometry`, `solve_z`, `reconstruct`, `transfer_time` |
| `fortran/contour_table_zero_rev.inc`, `fortran/contour_table_multi_rev.inc` | Compiled-in estimate tables (about 66 KB), generated by `tools/gen_table.py` and `tools/gen_mrev.py` (`tools/mrev_table.py` holds the shared multi-revolution functions) |
| `fortran/contour_simple.f90` | Short reference version (module `contour_simple`, `contour_simple_one`, same arguments as `contour_one`): the same time function, ODE derivatives and confluent step with closed-form starters, no tables, contours or safeguards. Tested against `contour_one` by `contour_simple` |
| `fortran/lambert_api.f90` | Dimensional API (`initialize_lambert`, `solve_lambert`, `solve_all_lambert`) with physical units, an explicit plane for antipodal geometry and structured status codes |
| `matlab/lambertContour.m`, `matlab/lambertContourFast.m` | MATLAB reference of the paper's method (accurate and fast modes, over the private `contourEngine.m`). Lamberts-Comparison's `run_tests` checks the native solver against it |
| `tests/` | Standalone CTests (below) |

The tables are pulled in with Fortran `include`, so no data file is read at
run time. On Apple platforms `CMakeLists.txt` defines `CONTOUR_APPLE_SINCOS`,
which calls the system `__sincos_stret` (one call for sine and cosine);
elsewhere the C `sincos` is used.

## Usage

Inputs use $\mu = 1$ in consistent units; for other $\mu$, scale time by
$\sqrt\mu$ (or use `lambert_api`).

```fortran
use confluentcontour
call contour_initialize()       ! optional; calls initialize lazily and thread-safely
call contour_one(r1,r2,tof,direction,v1,v2,status,half,nrev,branch)
call contour_batch(n,r1,r2,tof,direction,v1,v2,status,half,nrev,branch)
```

`contour_batch` takes column-major `3 x n` vectors, processes cases in staged
chunks (OpenMP parallel over chunks in the parallel build), and returns
results identical to `contour_one` bit for bit.

| Status | Meaning |
| ---: | --- |
| 0 | Solution found |
| 1 | Coincident multi-revolution roots at minimum time |
| 5 | Flight time below the multi-revolution minimum (branch infeasible) |
| -1 | Invalid input |
| -2 | Nearly collinear geometry: transfer plane undefined |
| -4 | No sufficiently accurate root |

`half` is -1 for degenerate, 0 for ordinary, and +1 for near-collinear
geometry (transfer plane poorly conditioned).

Optional scalar outputs expose the accepted coordinate and safeguard usage:

```fortran
type(contour_diagnostics) :: diagnostics
call contour_one(r1,r2,tof,direction,v1,v2,status,half, &
                 fast=.false.,diagnostics=diagnostics)
! diagnostics%z, %q_upper, %relative_tof_residual, %used_safeguard
```

`fast=.false.` only changes the rarely used interval-contour safeguards (more
nodes and a tighter `5e-13` residual gate). `q_upper` is NaN when unused. When
calling `solve_z` and `reconstruct` separately, forward `q_upper` to
`reconstruct(...,q_upper=q_upper)` to keep upper-boundary accuracy.

## Build and test

Requires CMake 3.20+ and GNU Fortran. OpenMP parallelizes `contour_batch` chunks; use `-DCONFLUENTCONTOUR_OPENMP=OFF` for a serial build.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
```

| Test | Checks |
| --- | --- |
| `test_contour_port` | Analytic truth; serial and OpenMP output identity |
| `test_contour_coordinates` | Upper-boundary coordinates, merged/infeasible roots, parabolic continuity, short hyperbolic arcs |
| `test_contour_tables` | Table-based feasibility at $t_{\min}(1\pm\delta)$, $\delta=10^{-1}\ldots10^{-6}$, against an independent golden-section minimum |
| `test_contour_batch` | `contour_batch` equals `contour_one` bit for bit on 5003 mixed cases, including invalid inputs |
| `test_contour_simple` | ContourSimple against `contour_one`: elliptic, both hyperbolic ways, near-parabolic, 1–10 revolutions and infeasible counts |
| `test_lambert_api` | Dimensional API: units, statuses and the explicit transfer plane |
| `test_near_antipodal_api`, `test_near_coincident_api` | Near-antipodal and near-coincident geometry by independent two-body propagation |

CI runs these on Linux x86-64, Linux ARM64 and macOS, with OpenMP on and off.

To regenerate the tables (NumPy required), run the commands below. The shipped tables are `gen_table.py 32` and `gen_mrev.py 16 24 OUT 128`.

```sh
python tools/gen_table.py 32 fortran/contour_table_zero_rev.inc
python tools/gen_mrev.py 16 24 fortran/contour_table_multi_rev.inc 128
```

When the library is loaded into MATLAB through a MEX gateway (as in Lamberts-Comparison), the gateway should keep the OpenMP runtime mapped (`RTLD_NODELETE` where available), since MATLAB threads retain its cleanup callbacks. Restart MATLAB before rebuilding a loaded native library.
